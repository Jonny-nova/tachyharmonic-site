# Working in this website repository

- Jonny owns product decisions. An idea, draft, or a document's claim that intent is settled is not evidence of his approval.
- Start with [README.md](README.md) and the current snapshot in [docs/PROJECT_MEMORY.md](docs/PROJECT_MEMORY.md). Follow the README's proportionate working procedure.
- Keep topic-specific authority intact: the adjacent master brand system governs brand and experience, its logo specification governs the mark, and [docs/BOOKING_SYSTEM_SPEC.md](docs/BOOKING_SYSTEM_SPEC.md) governs booking economics. Use the README's authority links; do not copy or silently revise those rules here.
- One person owns integration when substantive work spans components. Coordinate overlapping implementation before editing; routine one-person corrections need no formal assignment or check-in.
- Check the integrated visitor experience, not just individual files or tests. Keep implementation checks, independent verification, Jonny's acceptance, and publication distinct.
- When Jonny meaningfully changes an intention, record its evidence and reconcile only the dependent work. Preserve the earlier decision and link any refinement or supersession in project memory.
- The central coordinator should read `../.codex/coordinator-working-note.md` if it exists and use it at meaningful handoffs; work from the README and project memory when it is absent. Update the note after a material correction.
- Do not send that note to delegated agents. Tell them not to read or forward it; give them only corrected task requirements and boundaries. This is a behavioural boundary, not technical access control: agents share the filesystem. See the README procedure.
